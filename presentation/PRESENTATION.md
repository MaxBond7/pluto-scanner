# Pluto Scanner

## Программный комплекс для исследования эфира на ADALM-PLUTO / Pluto+

- Спектр, водопад, VFO, демодуляция
- Поиск новых контактов и сравнение фона
- Реальный свип 325 МГц – 3.8 ГГц
- Пассивный дрон-монитор 433 МГц – 5.8 ГГц

---

# Задача

## Что было нужно

- SDR-железо есть, а удобного рабочего места для исследования эфира — нет.
- Нужно видеть не только «картинку», но и **историю**: что было фоном, что появилось.
- Нужен инструмент под Windows, который запускается ярлыком и не требует терминала.
- Отдельная задача — **пассивно следить за полосами дроновых линков**.

## Ограничение, которое приняли сразу

> Pluto — это приёмник, а не радар и не декодер протоколов.
> Он может показать **радиосигнал**, но не может сам по себе назвать модель дрона, направление и дальность.

---

# Что это сейчас

## Pluto Scanner

- Desktop-приложение на **Python + PySide6 + pyqtgraph**
- Работает с **ADALM-PLUTO / Pluto+** и с симулятором
- Windows, запуск через ярлык **без консоли**
- Один или два SDR одновременно
- Три рабочих вкладки:
  - **Контакты**
  - **Сканер диапазона**
  - **Дрон-монитор**
- Результаты — в обычном **JSON**

---

# Базовые возможности

## Приём и анализ

- Спектр в dBFS и прокручиваемый водопад
- Программный VFO: перенос по частоте в цифре
- «Качание» VFO (wobble)
- Демодуляция **AM / FM / SSB / CW**
- Шумоподавитель и вывод звука
- Список контактов: ID, хиты, «новый», «известный»
- Сохранение известных частот между запусками

## Что даёт

- Можно слушать сигнал, не перестраивая LO
- Контакты не теряются при перестройке
- Один интерфейс для обзора и прослушивания

# Реальный сканер диапазона

![Сканер диапазона](ui_scanner.png)

- Свип **325 МГц – 3.8 ГГц**
- Шаг ~819 кГц при 1.024 MS/s
- Около **4240 шагов**, 12–18 минут
- Живой график: текущий шаг + накопленный максимум
- Прогресс, ETA, пропущенные шаги
- Сохранение фона и автоматическое сравнение

---

# Как работает сканер

## Свип

- Первый центр = `от + полоса/2`
- Последний = `до − полоса/2`
- Захваченные полосы точно покрывают диапазон
- На шаг — два свежих кадра
- Средний PSD шага → детектор
- Шумовая дорожка = медиана PSD шага
- Спур LO в центре вырезается

## Результат

- `step_XXXXX.json` — спектр и пики шага
- `background.json` — весь скан
- `compare.json` — отчёт сравнения

---

# JSON и сравнение фонов

## Что хранится

- `scan_version`, диапазон, шаг, полоса, FFT
- Метаданные устройства и усиления
- Пики: частота, ширина, SNR, тип, уверенность
- `max_hold_db`, `mean_db`, `coverage`

## Как сравниваем

- **По пикам:** новый пик без пары в фоне → новый контакт
- **По спектру:** подъёмы max-hold → широкополосные изменения
- Сравнение только по **пересечению диапазонов**
- Фон с другого устройства/усиления/формата — не применяется автоматически
- Так избегаем ложных «новых контактов»

# Классы и тревоги

| Класс | Признаки | Тревога |
|---|---|---|
| `FHSS` | короткие узкие посылки, скважность | да |
| `TELEMETRY` | редкие узкие посылки | да |
| `VIDEO_ANALOG` | непрерывный канал 3–10 МГц | да |
| `VIDEO_DIGITAL` | широкий канал 8–30 МГц | да |
| `WIFI` | 15–30 МГц, «плоский» спектр | нет |
| `NARROW` | узкий непрерывный носитель | нет |
| `UNKNOWN` | прочая активность | нет |

## Защита от ложных тревог

- Кандидат → оранжевый
- Тревога → красный, только после **3 попаданий** и **70% уверенности**
- Настройки: «Тревога после», «Мин. увер.»
- В таблице видно **«Хиты»**

# Два Pluto+

## Что дают

- Больше покрытия
- Параллельные полосы
- Разные антенны
- Резерв, если один линк деградирует

## Что показали реальные тесты

| Режим | Результат |
|---|---|
| 1 Pluto, 20.48 MS/s | стабильно |
| 2 Pluto, 10.24 MS/s | стабильно, события от обоих |
| 2 Pluto, 20.48 MS/s | 10 с работает, через 30 с одно отваливается |

Причина — общая USB-шина/питание, а не DSP.
Для двух потоков 20.48+ нужен **Gigabit Ethernet** или разные USB-контроллеры.

# Архитектура

```text
IQ (Pluto / симулятор)
  -> DeviceSession
     -> SpectrumAnalyzer -> detector -> tracker -> contacts
     -> VFO -> demod -> audio
     -> iq_ready (для дрон-монитора)

Сканер:
  ScanController -> peaks -> recorder -> compare

Дрон-монитор:
  DroneWatchController -> features -> tracker -> recorder
  DroneMonitorManager  -> несколько устройств, события, тревоги
```

- Один QThread на устройство
- DSP и GUI — в главном потоке
- Медленный USB не блокирует отрисовку
- Json-логи не требуют базы данных

# Надёжность и работа над ошибками

## Проверки

- **64 автотеста**: DSP, сканер, дрон-монитор, JSON, сравнение
- Симулятор: полный тракт, события, скриншоты
- Реальные Pluto+: IQ, спектр, свип, 2.4/5.8, два устройства
- Ярлык Windows: запуск без терминала

## Что исправляли

- «Демо-сканер» на QTimer → реальный свип
- Ошибка `QAbstractItemView.ResizeMode`
- Пропуски на графике из-за NaN
- Устаревшие кадры при перестройке LO
- Аудио во время сканирования
- Ложные контакты при сравнении с другим фоном
- Ложные тревоги → подтверждение событий
- USB `Broken pipe` → понятная ошибка и остановка

# Ограничения

## Честно

- **dBFS, не dBm** — нужна калибровка тракта
- Классификация — **гипотезы по форме спектра**, не декодирование
- Нет модели дрона и протокола
- Нет направления и дальности
- Remote ID требует отдельного Wi-Fi/BLE-приёмника
- 5.8 ГГц зависит от конкретного Pluto+
- Два SDR на одной USB-шине не дают 2× скорости
- Wi-Fi/Bluetooth дают похожие сигналы
- Реального дрона в тестах не было — только кандидаты
