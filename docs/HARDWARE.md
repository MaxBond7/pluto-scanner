# Аппаратура и что она даёт

## Есть сейчас

| Устройство | Состояние | Что даёт |
|---|---|---|
| Pluto+ / ADALM-PLUTO | работает по USB, прошивка 1R1T | спектр, сканер, дрон-монитор, запись IQ |
| KerberosSDR | есть, без антенн | 4 когерентных RX-канала, будущий фазовый пеленг |
| 2 × Baofeng | есть, со штатными антеннами | известный узкополосный FM-источник для проверки приёма |
| Старый роутер | есть | 2.4 ГГц Wi-Fi как тестовый сигнал; LAN-порты как свитч/точка доступа |
| ПК | один Ethernet | интернет занят; для второго устройства нужен адаптер или свитч |
| Диск Z: | 1 ТБ | физические бэкапы |

## Чего не хватает

- 4 одинаковые антенны для KerberosSDR и 4 коаксиальных кабеля;
- делитель/аттенюатор для подачи одного тестового сигнала на все каналы;
- USB-Ethernet адаптер или свободный порт/свитч для Pluto по сети;
- GPS-приёмник для карты;
- генератор/эталон для калибровки в dBm;
- второй Pluto, если нужны две независимые полосы.

## Что можно проверить уже сейчас

- Pluto: сканер и дрон-монитор на реальном эфире.
- Роутер: Wi-Fi 2.4 ГГц как источник для проверки детектора и белого списка.
- Baofeng: узкополосный FM на 433 МГц для проверки демодуляции и тревог.
- Kerberos: определить 4 RTL-SDR в Windows, проверить синхронный захват
  и встроенный источник шума. Пеленг без антенн невозможен.

## Ограничения KerberosSDR

- 24–1700 МГц; 2.4/5.8 ГГц требуют даунконвертера.
- 8 бит, около 2.4 MS/s на канал.
- Для пеленга нужны 4 антенны с известной геометрией и разносом,
  фазовая калибровка и прямая видимость.
- Официальный софт в основном Linux/Raspberry Pi; Windows надо проверять.

## Сколько реально тянет Pluto по USB 2.0

Измерено на PlutoSDR Rev.C (Z7010-AD9364), USB 2.0, ПК с одним портом
04.11.2026. Писалась одна и та же длительность, сравнивалось время.

| Полоса | Реальное время | Что это значит |
|---|---|---|
| 1.024 МГц | 100% | штатный режим приложения |
| 2.048 МГц | 101% | без потерь |
| 4.096 МГц | 101% | без потерь, самая широкая безопасная полоса |
| 6.144 МГц | 98% | на грани, иногда теряются отсчёты |
| 8.192 МГц | 74% | отсчёты теряются |
| 20.48 МГц | 29% | пишется меньше трети эфира, время в записи рвётся |

Выше 6 МГц у платы не хватает пропускной способности USB: приёмник
продолжает оцифровывать эфир, а до ПК доходит только часть буферов. Такую
запись нельзя использовать для временных признаков — в ней дыры.

Поэтому 20 МГц на этой плате — не «медленно», а **невозможно без потерь**.
Максимум для честной записи: 4.096 МГц (4 МГц полосы). Для более широкого
обзора нужен Pluto по сети (Ethernet) или USB 3.0 платформа.

Записать эфир без графического интерфейса:

```powershell
.\.venv\Scripts\python.exe -m tools.capture_pluto `
  --center 2412e6 --rate 4.096e6 --seconds 5 --label WIFI
```

Файлы попадают в `iq_recordings/` в том же формате, что и из приложения.

## Меры безопасности

- Baofeng передаёт только в разрешённом диапазоне/на разрешённой мощности
  или в эквивалент нагрузки/аттенюатор. Не подключать передатчик напрямую
  к SDR.
- Перед передачей проверять местные правила и не мешать другим службам.
- Kerberos и Pluto — только пассивный приём, пока явно не включён тестовый
  передатчик с аттенюатором.
