# HackRF One

## Зачем

Pluto по USB 2.0 честно держит 4.096–6.144 МС/с (см. `docs/HARDWARE.md`).
HackRF One даёт **2–20 МС/с** и диапазон **1 МГц – 6 ГГц**. Этого хватает,
чтобы:

- видеть полосу 20 МГц целиком, а не кусками по 5.5 МГц;
- ловить перескоки OcuSync/RC (1–2 мс) и анализировать их поведение;
- в будущем декодировать **DJI DroneID** (он передаётся и при выключенном
  Remote ID) и стандартный Remote ID.

Приём только. Передача не реализована и не планируется.

## Статус

Слой устройства готов и собирается в приложении: `sdr_scanner/devices/
hackrf.py`, пункт «Устройство → Добавить HackRF» и кнопка «+ HackRF».
**Проверен на живой плате** 06.11.2026 (HackRF One, серийный номер
`...c66c63dc34735483`): 20 МС/с, поток около 99% реального времени,
дрон-монитор и глубокий взгляд работают. Ограничения, пересчёт усиления,
выбор фильтра, список устройств и отсутствие библиотеки покрыты тестами.

Перед первым подключением исправлен вызов `hackrf_device_list`: libhackrf
возвращает указатель напрямую и не принимает аргументов. Также реальная
скорость теперь приводится к 20.0 МС/с — иначе монитор сравнивал бы 20.48
с фактическими 20.0 и отбрасывал все блоки.

Для первой проверки есть `tools/check_hackrf.py` (см. ниже).

## Установка на Windows

1. **Драйвер.** Скачать [Zadig](https://zadig.akeo.ie/), включить
   `Options → List All Devices`, выбрать `HackRF One`, поставить драйвер
   **WinUSB** (не libusbK, если не уверены).
2. **libhackrf.** Взять сборку `hackrf-tools` для Windows (страница релизов
   Great Scott Gadgets / Pothosware). Проверить в консоли:

   ```powershell
   hackrf_info
   ```

   Должны появиться серийный номер и прошивка.
3. **DLL.** Скопировать `hackrf.dll` из `hackrf-tools\bin` в одну из папок:
   - рядом с `SDRScanner.exe` (или в `_internal` для установленной версии);
   - в `C:\Windows\System32`;
   - в любой каталог из `PATH`;
   - либо указать полный путь в переменной окружения `HACKRF_DLL`.

   Без DLL приложение напишет «не найдена libhackrf» и не упадёт.

   Проверенная на этой машине сборка требует рядом с `.exe` три файла:
   `hackrf.dll`, `libusb-1.0.dll`, `pthreadVC2.dll`. Они есть, например,
   в Windows-сборке SDR++; можно взять `hackrf.dll` оттуда, а `libusb`
   и `pthread` положить в ту же папку. Не смешивайте DLL от разных версий
   без проверки: `hackrf_info` должен видеть плату.

4. **В приложении:** «Устройство → Добавить HackRF» или кнопка «+ HackRF»,
   либо запуск `python -m sdr_scanner --hackrf`.
   Устройство появится в списке как `HackRF 1 (xxxxxx)`.

## Linux / macOS

```bash
sudo apt install libhackrf0 hackrf        # Debian/Ubuntu
sudo cp /etc/udev/rules.d/..              # правила udev из пакета hackrf
```

На macOS — `brew install hackrf`. Библиотека ищется как `libhackrf.so.0`
или `libhackrf.dylib`.

## Первая проверка на живой плате

Перед запуском интерфейса:

```powershell
.\.venv\Scripts\python.exe -m tools.check_hackrf
```

Скрипт снимет 2 секунды на 2437 МГц при 20.48 МС/с и покажет:

- серийный номер и версию библиотеки;
- реальную скорость потока (должна быть близка к 20.48 МС/с);
- перегрузку АЦП (должна быть около 0 %) и DC-смещение;
- пик спектра и шумовую дорожку;
- скважность, пачки, перескоки и число каналов на полосе 20 МГц.

Полезные варианты:

```powershell
# другая частота и усиление
.\.venv\Scripts\python.exe -m tools.check_hackrf --freq 5800e6 --gain 24

# сохранить IQ для разбора
.\.venv\Scripts\python.exe -m tools.check_hackrf --out Z:\hackrf_2437.cf32
```

Если скрипт пишет «не найдена libhackrf», сначала установите DLL по
инструкции выше. Если поток медленнее запрошенного — проверьте кабель,
порт USB 3.0 и драйвер WinUSB.

## Параметры

| Параметр | Значение | Примечание |
|---|---|---|
| Частота | 1 МГц – 6 ГГц | ниже 30 МГц чувствительность падает |
| Полоса | 2–20 МС/с | 2.048 / 4.096 / 6.144 / 10.24 / 20.48 |
| Фильтр | 1.75–28 МГц | подбирается автоматически до ближайшего |
| Усиление | LNA 16 дБ + VGA 0–62 | ползунок приложения задаёт VGA |
| AMP | +14 дБ | включается при усилении ≥ 70 |
| АЦП | 8 бит | меньше динамический диапазон, чем у Pluto |

Для 2.4 ГГц разумно начинать с **20.0 МС/с** (HackRF тянет это по USB 2.0
без потерь, в отличие от Pluto) и усиления 32–40. В списках приложения есть
и 20.48 МС/с: libhackrf всё равно ограничит её до 20.0, и монитор теперь
сравнивает с фактической скоростью, а не с запрошенной.

Плата открывается на **20.0 МС/с**. Дрон-монитор и глубокий взгляд
используют ту скорость, с которой она уже работает: libhackrf ненадёжно
перезапускает поток при смене скорости на ходу. Поэтому смена скорости
HackRF в главном окне заблокирована — для другой скорости перезапустите
приложение (или добавьте плату заново). Это же убирает ошибку
`start_rx: -1000` после остановки монитора.

## Ограничения

- 8 бит: слабые сигналы рядом с сильными хуже видны, чем на 12-битном Pluto.
- Нет TCXO: частота может уходить на десятки ppm; для точных измерений
  нужен клок 10 МГц или калибровка.
- Полудуплекс: приём и передача одновременно невозможны.
- Bias tee в базовой плате нет — активные антенны требуют внешнего питания.

## Что дальше

Когда плата появится:

1. Снять 5–10 с на 2.4 ГГц при 20 МГц и посмотреть перескоки OcuSync.
2. Проверить захват DroneID (`docs/DATASETS.md`, проект `proto17/dji_droneid`).
3. Добавить в приложение режим «широкая полоса» с анализом прыжков и
   декодированием Remote ID/DroneID.

## Правовое

Только пассивный приём. Передача, глушение и подмена — вне проекта.
