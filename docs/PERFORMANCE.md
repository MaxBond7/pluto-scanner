# Производительность

## Как измеряем

```powershell
.\.venv\Scripts\python.exe tools\bench.py --repeat 12
```

Скрипт меряет горячие пути без платы и без GUI: спектр, детектор, поиск
пиков, прореживание, трекер, признаки дрон-монитора, сборку темы, сдвиг
водопада. Для UI-путей (обновление графика) — отдельный замер с Qt.

## Запуск

Приложение показывает **загрузочный экран** через ~125 мс после старта — до
того, как импортируются pyqtgraph и панели интерфейса. Это и есть «мгновенный
отклик»: пользователь видит летящую птицу, полосу загрузки и названия этапов,
а не пустой экран.

| Этап | Время |
|---|---:|
| импорт PySide6 + `QApplication` | ~113 мс |
| **загрузочный экран на экране** | **~125 мс** |
| preload pyqtgraph + UI (в фоне, экран анимируется) | ~420 мс |
| сборка окна | ~240–470 мс |
| **полностью готовое окно** | **~1.0–1.2 с** |

Экран рисует ASCII-птицу, у которой часть символов гаснет и появляется
(кадр раз в 55 мс), и полосу с этапами: `ГРАФИКА` → `ИНТЕРФЕЙС` → `ТЕМА` →
`СБОРКА ОКНА` → `ГОТОВО`. Флаг `--no-splash` отключает его, в режимах
скриншотов он не показывается.

| Этап | Было | Стало |
|---|---:|---:|
| импорт `pluto_scanner` (numpy, Qt, pyqtgraph, scipy) | 1040 мс | **482 мс** |
| сборка окна | 242 мс | 242 мс |
| **до видимого окна** | **~1380 мс** | **~721 мс** |

Главная причина — `scipy`. Импорт `scipy.signal` стоит ~528 мс,
`scipy.ndimage` — ~235 мс, а использовались они ровно для трёх
одномерных операций. Что сделано:

- `scipy.ndimage` заменён на `pluto_scanner/dsp/arrayops.py`:
  медианный фильтр, «закрытие» зазоров и разметка пробегов — всё на NumPy;
- `scipy.signal.get_window` заменён на свои окна Ханна/Хэмминга/Блэкмана
  (`get_window` в том же модуле, экзотические имена падают в SciPy);
- `scipy.signal.find_peaks` в классификаторе заменён на подсчёт локальных
  максимумов с prominance;
- `dsp/demod.py` импортирует `scipy.signal` **лениво** — только когда
  реально включается звук; сразу после показа окна его подгружает фоновый
  поток, чтобы первый клик «Аудио» не ждал;
- `scipy.io.loadmat` уже был ленивым.

## Что было и что стало

Замеры на одном ноутбуке, медиана из 12 прогонов. «Было» — до правок,
«стало» — после.

| Операция | Было | Стало | Ускорение |
|---|---:|---:|---:|
| спектр 1.024 МС/с, блок 200 мс, nfft 2048 | 2.50 мс | **1.18 мс** | 2.1× |
| спектр 20.48 МС/с, блок 20 мс, nfft 4096 | 6.15 мс | **3.17 мс** | 1.9× |
| признаки дрона (`analyze_iq`, блок 20 мс) | 12.58 мс | **5.68 мс** | 2.2× |
| прореживание спектра 4096 → 256 | 0.82 мс | **0.01 мс** | 80× |
| прореживание 8192 → 1024 (шаг сканера) | 3.27 мс | **0.03 мс** | 100× |
| обновление графика спектра (UI) | 2.62 мс | **0.19 мс** | 13.8× |
| детектор, 4096 бинов | 0.03 мс | 0.03 мс | — |
| поиск пиков, 8192 бина | 1.24 мс | 1.18 мс | — |
| трекер контактов, 6 детекций | 0.03 мс | 0.03 мс | — |

Что это значит на практике:

- дрон-монитор: один блок 20 мс теперь считается ~5.7 мс вместо ~12.6 мс;
  при dwell 40 мс это ~14% одного ядра на устройство вместо ~31%;
- основной экран: обновление графика упало с 2.6 мс до 0.19 мс на кадр —
  при 20 FPS это 4% ядра вместо 52%;
- сканер: прореживание спектра для JSON перестало занимать больше времени,
  чем сам поиск пиков.

## Что именно изменено

1. **`decimate_mean`** — был цикл Python по сотням срезов с `np.mean` в
   каждом. Заменён на `np.add.reduceat` (один вызов C). Это самая частая
   операция: она выполняется для каждого кадра и каждого шага сканера.

2. **`SpectrumAnalyzer.compute`** — три правки:
   - окно применяется на месте, без лишней копии блока;
   - в `complex128` конвертируются только те сегменты, которые реально
     попадают в FFT (раньше конвертировался весь блок — до 6.4 МБ на кадр);
   - `fftshift` делается над одномерным PSD, а не над матрицей 32 × nfft;
   - мощность считается как `re² + im²`, без `abs()` (не нужен корень).

3. **`_time_features` дрон-монитора** — `abs(chunk.astype(complex128))**2`
   заменено на работу в `complex64`/`float32`. На блоке 400 тыс. отсчётов
   это убирает конвертацию 6.4 МБ и двойной проход.

4. **График спектра** — на каждом кадре создавались и удалялись до семи
   `TextItem` (метки детекций). Теперь есть пул из семи меток, которые
   только переставляются и скрываются. Это и дало 13.8×.

5. **Статус «Фон: готов»** — `setStyleSheet` вызывался каждый кадр, а Qt
   заново разбирает таблицу стилей. Теперь только при смене состояния.

## Интерфейс и окна (04.11.2026)

| Что | Было | Стало |
|---|---:|---:|
| таблица контактов, 200 строк | 8.5 мс каждые 400 мс | **2.1 мс** |
| обновление строки события в дрон-мониторе | 12 ячеек всегда | только изменившиеся |
| статус монитора (раз в кусок) | `setStyleSheet` каждый раз | только `setText` |
| кадр спектра при свёрнутом окне | полная перерисовка | **пропуск** |
| подпись калибровки | `setStyleSheet` каждый кадр | только при смене |
| FPS и число контактов | каждый кадр | 4 раза в секунду |

Таблица контактов больше не пересоздаёт 9 ячеек на контакт: строки
переиспользуются, цвета берутся из кэша (тема меняется редко), а строка,
у которой не изменился ни текст, ни цвет, ни подсказка, пропускается
целиком.

Переключение темы остаётся ~0.37 с: это Qt заново применяет таблицу стилей
ко всем виджетам приложения. Скрытое окно монитора при этом не перекрашивается
— оно получает цвета при показе.

## Окна

- Окно дрон-монитора запоминает размер и положение в `settings.json` и
  открывается там же, где его закрыли; первый запуск центрируется на экране.
- Окно — самостоятельное (не дочернее у главного). На Windows у дочернего
  окна нет кнопки в панели задач, и при сворачивании оно превращается в
  маленькую полоску заголовка; теперь оно сворачивается нормально.
- Кнопка-ярлык поднимает окно из панели задач (`show()` сам по себе этого не
  делает на Windows), сохраняя развёрнутое состояние.
- Закрытие окна скрывает его и не останавливает мониторинг.

## Контроль регрессий

`tests/test_performance.py` содержит:

- **сверку с эталоном**: `decimate_mean` сравнивается с прежней реализацией
  на цикле, спектр — с независимым расчётом через `fftshift` + `abs²`;
- **бюджеты**: с запасом 3–5× от измеренного, чтобы медленная CI-машина не
  падала, но реальная регрессия (цикл по бинам, копия блока, аллокация на
  кадр) ловилась.
- **таблица контактов**: 200 строк должны обновляться быстрее 6 мс; проверка
  ловит возврат к пересозданию всех ячеек на каждом тике.
- **окна**: геометрия дрон-монитора сохраняется и восстанавливается,
  `show_and_raise` поднимает свёрнутое окно.

## Что ещё стоит знать

- Водопад по-прежнему сдвигает историю на кадр (200 × nfft). При nfft 2048
  это ~0.5 мс; узкое место — не сдвиг, а загрузка текстуры в Qt.
- Сканер делает шаг примерно за 2 блока по 200 мс — это ограничение
  перестройки LO, а не вычислений.
- Полный обзор 325–3800 МГц занимает минуты: 16 МГц на шаг при 20.48 МС/с.
  Это физика перестройки, не оптимизация.
