# Model card: Pluto Scanner drone ML

## 1. Модель

| Поле | Значение |
|---|---|
| Название | `pluto-scanner-drone-softmax` |
| Версия | `1` (внутри файла модели) |
| Версия приложения | `0.13.0` |
| Тип | softmax-регрессия на 12 признаках IQ |
| Файл по умолчанию | `assets/ml_model_default.json` |
| SHA256 | `a46eff390bcfe3f1ef144f49c5fcdb0383986692981b3052ef86559ee68211e8` |
| Лицензия весов | MIT (сгенерированы из MIT-кода и синтетики) |
| Вход | признаки `DroneObservation`, не сырой IQ |
| Выход | top-3 класса + вероятность |

Классы: `FHSS`, `TELEMETRY`, `VIDEO_ANALOG`, `VIDEO_DIGITAL`, `WIFI`,
`NARROW`.

## 2. Назначение

Модель даёт **вторую гипотезу** к эвристическому классификатору
дрон-монитора. Она не заменяет эвристику, не поднимает тревогу сама и не
декодирует протокол.

Использовать можно:

- как подсказку в карточке события;
- для сравнения с эвристикой;
- как baseline для локального дообучения.

Нельзя использовать как:

- единственный детектор;
- доказательство модели дрона;
- Remote ID;
- средство определения дальности/направления;
- сертифицированное средство безопасности.

## 3. Данные обучения

Обучение только на **синтетическом IQ**, сгенерированном кодом проекта:

- 60 блоков на класс, 360 блоков;
- генератор: `pluto_scanner/ml/synthetic.py`;
- seed `1`;
- 600 эпох, Adam, L2 `1e-3`;
- train/test split стратифицированный, 20% test.

Сторонние датасеты в обучение **не входили**. Это важно: модель не содержит
данных DroneRF/DroneDetect/CC BY-NC.

## 4. Метрики

### Отложенная синтетическая выборка

- accuracy: **94.4%**;
- 72 примера;
- согласие с эвристикой: 25.8%.

### Domain-gap (31.10.2026)

| Домен | N | Accuracy | Confidence |
|---|---:|---:|---:|
| synthetic fresh | 94 | 98.9% | 91.9% |
| synthetic augmented | 89 | 95.5% | 85.6% |
| real Baofeng 433 / NARROW | 11 | **72.7%** | 69.1% |

Реальные ошибки: `NARROW` → `TELEMETRY` (2), `NARROW` → `FHSS` (1).
Подробности: `docs/DOMAIN_GAP.md`.

## 5. Ограничения

- Синтетика ≠ реальный эфир; реальная точность ниже.
- Обучена только на одном генераторе и одном наборе параметров.
- Не видела реальных Wi-Fi/Bluetooth/FPV-записей.
- Чувствительна к перегрузке входа; перегрузка отсекается отдельным
  правилом.
- Не учитывает антенну, усиление, кабель и многолучёвость.
- Не является определителем модели дрона.
- Не заменяет Remote ID.

## 6. Риски и смещения

- **Domain gap**: реальные сигналы «грязнее» синтетики.
- **Overconfidence**: высокие вероятности на синтетике не гарантируют
  реальную уверенность.
- **Label bias**: классы заданы эвристикой/синтетикой, а не экспертной
  разметкой.
- **Front-end overload**: мощный сигнал вблизи может выглядеть как FHSS;
  исправлено флагом `OVERLOAD`.
- **Environment bias**: один город/антенна/усиление.

## 7. Проверка и воспроизведение

```powershell
python -m pluto_scanner.ml.train --per-class 60 --epochs 600
python -m pluto_scanner.ml.domain_gap
python -m pluto_scanner --domain-gap
```

Модель по умолчанию проверяется тестом `test_bundled_default_model_loads`.

## 10. Бинарная модель «дрон / не дрон»

Это **вторая, отдельная модель**. Она не заменяет шесть классов, а
отвечает на главный вопрос: «это дрон или нет?».

| Поле | Значение |
|---|---|
| Название | `pluto-scanner-drone-binary` |
| Тип | логистическая регрессия на 18 признаках спектра и огибающей |
| Файл | `assets/ml_drone_binary.json` |
| SHA256 | `7a40d9bc0a64543f903f3f111f93c0990a3f240be85686998ca53f0040436d88` |
| Размер | 6 063 байта |
| Признаки | `pluto_scanner/ml/binary_features.py` |
| Вход | 256-точечный спектр + огибающая из `DroneObservation` |
| Выход | одно число `P(дрон)` + вердикт `drone/candidate/background/unknown` |
| Порог тревоги | 0.952 (подобрано под FPR ≈ 1% на отложенной выборке) |
| Порог кандидата | 0.60 |
| Лицензия весов | MIT (обучены на CC BY 4.0 DroneRF + своих записях + синтетике) |

Метрики отложенной выборки (516 блоков, разделение по записям):

| Метрика | Значение |
|---|---|
| ROC-AUC | **0.978** |
| TPR при FPR 1% | **0.751** |
| Precision / recall при пороге 0.952 | 0.993 / 0.766 |
| Ложные тревоги | 1.2% |
| Калибровка, бина 0.9+ | средний score 0.97, реально дронов 93.6% |

По источникам (доля блоков выше порога):

| Источник | Блоков | Средний score | Выше порога |
|---|---:|---:|---:|
| DroneRF AR (чистые) | 145 | 0.987 | 93% |
| DroneRF Phantom (чистые) | 69 | 0.981 | 94% |
| DroneRF AR, ослабленные до 7–24 дБ | 88 | 0.893 | 64% |
| DroneRF Phantom, ослабленные | 48 | 0.843 | 25% |
| **DroneRF фон с чужим Wi-Fi** | 32 | 0.833 | **6.3%** |
| Рация Baofeng 433 (реальная) | 80 | 0.014 | **0%** |
| Синтетический Wi-Fi | 26 | 0.066 | 0% |
| Синтетический узкополосный | 28 | 0.014 | 0% |

Кросс-проверка по семействам (обучить без семейства, проверить на нём):
AR 0.73, Bebop 0.74, Phantom 0.47 при пороге 0.9. Phantom слабее всех:
его меньше в датасете и он слабее по уровню.

**Разброс.** Групп записей мало, поэтому одно разбиение — лотерея. По пяти
разбиениям того же набора: ROC-AUC 0.962 ± 0.054, TPR при FPR 1%
0.638 ± 0.338, recall дронов при 0.9 — 0.710 ± 0.098. Цифры выше — пример,
а не гарантия.

**Реальный Wi-Fi (01.11.2026).** На записях мобильной точки доступа
(2412 МГц) 44–64% блоков получают score выше порога тревоги. Если
добавить эти блоки в отрицательные, ложные тревоги падают до 3.4%, но
recall Phantom падает с 0.57 до 0.19, а TPR при FPR 1% — с 0.64 до 0.38.
Такой обмен не принят: модель с Wi-Fi в обучении не выпущена. Подробности
и числа — `docs/BINARY.md`.

Данные обучения:

- **DroneRF** (Al-Sa'd et al., 2019, CC BY 4.0, DOI
  `10.17632/f4c2b4n755.1`): реальные записи 2.4 ГГц Bebop / AR / Phantom
  и фон. Из 40 ГБ берутся окна по 20 мс с реальной передачей; «тихие»
  окна внутри дроновых записей отбрасываются, чтобы не учить шум как
  дрон. Половина положительных окон зашумляется до SNR 24/18/14/10/7 дБ.
- **Свои записи**: рация Baofeng 433 МГц (`NARROW`) как отрицательный
  пример.
- **Синтетика проекта**: только отрицательные примеры (Wi-Fi-подобные
  пачки и узкополосные несущие). Синтетические «дроны» в обучение **не
  идут**: генератор делает непрерывную несущую, а все реальные дроновые
  окна в DroneRF стробированы (скважность ≈ 0.4). Смешивание этих двух
  картин давало логистической модели противоречие и роняло ROC-AUC с
  0.97 до 0.85.

Почему не признаки эвристики: попытка обучить бинарную модель на тех же
12 признаках дала ROC-AUC **0.52**. Общий «пол» спектра ломается на
реальном тракте с кривым шумовым полом, и широкий видеолинк выглядит как
«узкая активность 15 кГц». Поэтому у бинарной модели свой устойчивый пол
(прямая под сигналом) и 18 относительных признаков; ROC-AUC вырос до
**0.97** на том же наборе.

Полные метрики, калибровка и кросс-проверка по семействам дронов —
`docs/BINARY_REPORT.md`. Описание и ограничения — `docs/BINARY.md`.

Ограничения, которые нельзя обойти этим датасетом:

- Wi-Fi-дрон (Bebop) физически неотличим от обычного Wi-Fi без
  декодирования MAC-адресов;
- модель не определяет модель дрона;
- 433/868/915 МГц подтверждены только синтетикой, не реальными дронами;
- калибровка верна для этого тракта и этой антенны.
