# Второй RX-канал Pluto+ (2R2T): проверка и план

## Коротко

Сейчас плата работает в режиме **1R1T**: прошивка отдаёт один комплексный
RX-канал. Второй антенный порт RX2 есть физически, но приложение его не
увидит, пока не появится 2R2T-прошивка.

Это ограничение прошивки/FPGA, а не Python-кода. Включать второй канал
«программно» нельзя: в потоковом устройстве просто нет второго I/Q.

## Что показала проверка

Команда:

```powershell
.\.venv\Scripts\python.exe -m pluto_scanner --rx-info
```

Результат на текущей плате:

```json
{
  "uri": "usb:1.6.5",
  "hw_model": "Analog Devices PlutoSDR Rev.C (Z7010-AD9364)",
  "firmware": "v0.37-dirty",
  "chip_model": "ad9364",
  "iio_rx_channels": ["voltage0", "voltage1"],
  "rx_channels": 1,
  "dual_rx": false,
  "mode": "1r1t"
}
```

Что это значит:

- `voltage0` + `voltage1` — одна комплексная пара I/Q, то есть один RX;
- для 2R2T должно быть четыре канала (`voltage0..voltage3`);
- попытка `rx_enabled_channels = [0, 1]` возвращает
  `RX mapping exceeds available channels`;
- `config.txt` на USB-диске также описывает `Z7010-AD9363`, а `hw_model`
  сообщает `AD9364` — это 1R1T-ветка.

Рядом с `rx_info.json` сохраняется тот же отчёт, его удобно приложить к
вопросу на форуме или сравнить до/после прошивки.

## Важно про RX1/RX2

Даже после включения 2R2T у AD9361 **один общий RX LO** на оба канала.
Второй канал — это вторая антенна на **той же частоте**, а не вторая
независимая полоса.

- две антенны на одной частоте: разнесение, сравнение уровней, фаза;
- две разные полосы одновременно: нужны два независимых Pluto.

## План A: проверить U-Boot environment (без прошивки)

Иногда 2R2T уже есть в текущей прошивке, но выключен настройками загрузчика.
Это обратимый шаг, но требует SSH/Serial и понимания риска.

1. Подключиться к Pluto по USB-сети:

   ```sh
   ssh root@192.168.2.1
   ```

   Стандартный пароль Pluto — `analog`, если он не менялся.

2. Сохранить текущее окружение:

   ```sh
   fw_printenv > /mnt/jffs2/uboot-env-backup.txt
   cat /proc/device-tree/model
   fw_printenv attr_name attr_val mode
   ```

3. Включить 2R2T (как это делает Pluto+ firmware):

   ```sh
   fw_setenv attr_name compatible
   fw_setenv attr_val ad9361
   fw_setenv mode 2r2t
   reboot
   ```

4. После загрузки проверить:

   ```sh
   cat /proc/device-tree/model
   fw_printenv attr_name attr_val mode
   ```

   И на компьютере:

   ```powershell
   .\.venv\Scripts\python.exe -m pluto_scanner --rx-info
   ```

   Успех: `rx_channels: 2`, `dual_rx: true`, `mode: 2r2t`, в
   `iio_rx_channels` четыре записи.

5. Откат, если стало хуже:

   ```sh
   fw_setenv attr_name
   fw_setenv attr_val
   fw_setenv mode
   reboot
   ```

На некоторых Pluto+ этот способ не срабатывает: нужен именно образ
прошивки, собранный с 2R2T HDL (см. issue `plutoplus/plutoplus#66`).
Если после перезагрузки пропали USB/сеть — переходить к DFU-восстановлению,
не трогая питание.

## План B: прошить 2R2T-прошивку

Перед любым обновлением:

- записать серийный номер, `hw_model`, версию прошивки и `config.txt`;
- сохранить калибровку/настройки, если они есть;
- скачать образ только из официального или проверенного репозитория;
- сверить SHA256;
- не отключать питание во время обновления.

Варианты:

1. **Официальная Pluto+ v1.33** — самая консервативная ветка:
   <https://github.com/plutoplus/plutoplus/releases/tag/v1.33>
   Старая (2021, на базе ADI v0.33), зато от производителя Pluto+.
2. **Bakstaaj v0.39** — более свежая сторонняя сборка с явным режимом 2R2T:
   <https://github.com/bakstaaj/N0JCG-PLUTO-FIRMWARE/releases>
   В `config.txt`:

   ```ini
   [AD936X]
   force_2r2t = 1
   attr_name = compatible
   attr_val = ad9361
   compatible = ad9361
   mode = 2r2t
   ```

   После сохранения и извлечения USB-диска — перезагрузка.

### Обновление через USB-диск (предпочтительно)

1. Скопировать `boot.frm` в корень диска `PlutoSDR`, если он есть в пакете.
2. Безопасно извлечь диск, но **не отключать USB-кабель**.
3. Дождаться, пока диск появится снова.
4. Скопировать `pluto.frm` (и `config.frm`, если требуется) в корень.
5. Снова извлечь диск и дождаться перезагрузки.
6. Проверить `rx_info.json` и `--rx-info`.

### DFU (только если USB-обновление не работает)

DFU — восстановительный путь, а не первый выбор. На Pluto+ нужно открыть
корпус и переставить перемычку USB reset:

- обычная ADI-прошивка ожидает `USRT-MIO52`;
- Pluto+ firmware с Ethernet — `USRT-MIO46`;
- вход в DFU: замкнуть `URST` на `MIO52`, нажать DFU и подать питание.

После DFU вернуть перемычку в рабочее положение. Если нет уверенности в
ревизии платы и перемычках — остановиться и не прошивать.

## Риски

- Неверный образ или клон платы может не загрузиться.
- Обновление загрузчика/DFU опаснее обычного `pluto.frm`.
- После смены прошивки может измениться MAC/IP, USB-режим, SSH-ключи.
- 2R2T может не включиться, если внутри реально AD9364/1R1T.
- Гарантий, что конкретная плата поддерживает 2R2T, по одной модели
  `hw_model` дать нельзя: нужна проверка FPGA-конфигурации или вскрытие.

## Что будет после успеха

Когда `--rx-info` покажет два канала, можно делать в приложении:

- одновременный захват RX1 и RX2;
- вторую спектральную дорожку/водопад;
- сравнение уровней и фазы на одной частоте;
- основу для разнесённого приёма и фазовых экспериментов.

До этого приложение остаётся в 1R1T-режиме: это честно и не создаёт
видимости поддержки, которой нет.
